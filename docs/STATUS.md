## 5. Решения, которых нет в `docs/rules.md` (на ваше решение — переносить ли)

Трактовки, зашитые в код/конфиг/промпт или описанные только в CONTEXT.md:

1. **Порог паузы без предупреждения — 180 с** (`settings.pause_threshold_s`); guard c06 → не выше 7. R7 говорит о паузе без предупреждения, но порога не называет. (CONTEXT §7.1)
2. **Что считается предупреждением об ожидании** — фразы из регулярки `_WAIT_WARNING` (`preprocess.py:71-79`: «ожидайте», «подождите», «минуту», «уточню/проверю», «please hold», «күте тұрыңыз»…). «Спасибо/извините за ожидание» ПОСЛЕ паузы предупреждением не считается (`:65-70`).
3. **Как считается пауза**: от первого неотвеченного сообщения клиента до следующей засчитываемой реплики оператора; время удержания вычитается; пауза «предупреждена», если последняя реплика оператора перед ней содержит предупреждение (`:342-355`).
4. **Первая реакция**: от события эскалации (чат) / «Агент присоединился» (звонок) до первой засчитываемой реплики оператора (`:337-340`).
5. **Словесная идентификация в звонке** фиксируется первой репликой оператора с фразой подтверждения («всё верно», «идентификация пройдена», «сәйкестендіру сәтті», «identity verified»…) после того, как клиент назвал замаскированные данные (`:80-87`, `:363-374`). R4 говорит «словесное в звонке», но не как определяется. (CONTEXT §7.2)
6. **Что не засчитывается оператору**: точные дубли (timestamp+speaker+text), реплики до подключения (IVR), на удержании и в консультации, после «Клиент завершил разговор». **not_evaluable — если нет ЗАСЧИТЫВАЕМЫХ реплик** (оператор, говоривший только на удержании, → not_evaluable; проверено пробой). R11 говорит «нет реплик оператора».
7. **Голосование при VOTES > 1**: binary/flag — большинство, ничья → первый голос; scale — нижняя медиана; N/A для шкалы побеждает только большинством (`evaluator.py:172-186`).
8. **Язык клиента** (для R2 «на языке клиента») определяется программно по всем сообщениям клиента: латиница > кириллица → EN; доля «казахских» слов ≥ 20 % → KZ, иначе RU (`preprocess.py:189-205`). Для смешанных сообщений (edge-kz-004) основной язык — KZ.
9. **Правило промпта П1** «каждый недостаток — ровно в одном критерии» + список остальных критериев в блоке критерия (`prompt.py:53-55`, `:170-172`). В rules.md отражено только для c06 (R7).
10. **Виды грубых нарушений** (`violation_type`): insult / off_platform_paid_service / confidential_disclosure / other (`prompt.py:23`).

## 7. Риски

1. **Эталон не проверен человеком** (`status: draft_by_claude_needs_human_review`); три итога правились по арифметике. Оставшиеся 15 расхождений частично — спорные места эталона (p4-ru-005/c03, p1-ru-029/c07, непоследовательность по c06).
2. **Переобучение на tune**: правки правил проверялись на тех же 55 диалогах. Единственная независимая проверка — holdout (запускает человек).
3. **Звонки — 3 в tune, 87.5 %**: самая слабая группа, выборка мала. На holdout/контроле звонки могут дать основную ошибку.
4. **c04/c06 — 89–91 %**: сложнее всего формализуются; система систематически строже эталона.
5. **Контрольный набор на 23-м часу** требует REST API + пакетной оценки (этап 4) — не начаты. Сейчас оценить набор можно только через `eval.run` с эталоном или прямым вызовом `Evaluator`.
6. **VOTES=1**: `confidence` везде 1.0 и неинформативна; финальный прогон с `--votes 3` ≈ ×3 стоимости (~$19 на tune).
7. **Повторный импорт того же `group_id` перезаписывает транскрипты** под существующими оценками (`db.py:211-220`); оценка хранит факты, но не снимок транскрипта.
8. **Отказ модели / `max_tokens`** по одному критерию переводит всю оценку в `failed` без повтора (`evaluator.py:64-70`); серверный fallback включён, так что отказы редки, но повтора нет.
