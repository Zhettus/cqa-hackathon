## 2. Что сделано по этапам

### Этап 0 — подготовка
- `scripts/split_gold.py`: `eval/gold_draft.json` → `gold_tune.json` (55) и `gold_holdout.json` (10) по полю `split`,
  строки копируются дословно, проверка объединения с исходником.
- `scripts/download_audio.py`: `audio_url` организаторов отдаёт **HTML-страницу плеера**; скрипт берёт `<source src>`
  (подписанная ссылка живёт ~1 ч, извлекается заново при каждом запуске). 5 mp3 в `data/audio/` (в `.gitignore`).
- `scripts/explore.py`: сводка по наборам (был до нас, запускался как есть).
- `docs/api_contract.md`: REST-контракт (наборы, диалоги, чек-листы с версиями, оценка и пакеты, результаты,
  апелляции, логи LLM). Явного «одобряю» не было — принят по факту реализации ядра по нему.

### Этап 1 — ядро (без LLM)
- `backend/data_source.py`: API по `group_id` (`DATA_API_URL`), fallback на `data/{group_id}.json`, проверка схемы
  pydantic, сохранение в БД. `import_upload` для ручной загрузки.
- `backend/db.py`: SQLite; таблицы `datasets, conversations, checklists, evaluations, criterion_results, llm_calls,
  appeals, appeal_decisions`. **Неизменяемость триггерами** (UPDATE/DELETE запрещены для версий чек-листов, оценок,
  результатов, логов, апелляций, решений). Статус апелляции выводится из наличия решения. Миграции — только
  `ADD COLUMN` (`_migrate`). Seed: чек-лист `chat-quality` v1 из `backend/checklists/default_v1.json`.
- `backend/checklist.py`: валидация структуры чек-листа.
- `backend/preprocess.py`: нумерация `idx` (1-based, = `n` в API), время в секундах (MM:SS, H:MM:SS, ISO 8601),
  флаги `duplicate / ivr / client_not_hearing / after_end / dtmf`, сегменты, `audio_offset_s` с вычетом пауз записи,
  факты (язык клиента и первой реплики оператора, эскалация, первая реакция, все паузы «клиент → оператор» с `warned`,
  `max_unwarned_gap_s`, `warned_gap_s`, удержание и консультации, идентификация system/verbal, `closing_event`,
  `operator_messages`, дубли). Дубли не удаляются из списка (нумерация сохраняется), исключаются через `visible_messages()`.
- `backend/scoring.py`: строго по SPEC, Decimal ROUND_HALF_UP до `settings.rounding_decimals`.

### Этап 2 — LLM и оценка
- `backend/llm/`: интерфейс `complete_json(system, user, schema, cache_prefix=)` → `(dict, Usage)`;
  `AnthropicProvider` (официальный SDK, structured outputs `output_config.format`, effort, кэш промпта на system
  и блоке диалога, серверный fallback `fallbacks="default"`), `OpenAICompatProvider` (httpx, `json_schema` →
  fallback на `json_object`, ретраи 5xx). Семафор параллельности, таймауты, цены (`KNOWN_PRICES` + `LLM_PRICE_*`).
  Ошибка аутентификации (`code="auth"`) прерывает оценку сразу.
- `backend/prompt.py`: system = роль + общие правила + **полный `docs/rules.md`** (+ правила для звонков);
  `cache_prefix` = канал/язык/факты/транскрипт `[#idx | говорящий | время | флаги] text` (+ `clean:`);
  user = описание критерия из конфига, ступени, N/A, подсказки, (с П1) список остальных критериев.
  Схема ответа строится из конфига: `evidence, checked_range, na_reason, reasoning, answer (+ violation_type)`.
  `prompt_version()` = `PROMPT_SCHEME` + хеш `prompt.py` и `docs/rules.md`.
- `backend/validator.py`: N/A только при `na_allowed`, допустимые ступени, существующий `idx`, цитата нечётко
  ≥ 0.85 по ОРИГИНАЛЬНОМУ тексту, `na_reason` при N/A, evidence или checked_range, (с П8) reasoning на русском.
  Ошибка → повтор с текстом ошибки, до 2 раз; иначе оценка `failed`.
- `backend/guards.py`: жёсткие правила из конфига критерия (`guards`); c06 `c06_timing`: первая реакция >
  `first_response_threshold_s` или `max_unwarned_gap_s` > `pause_threshold_s` → не выше 7. Срабатывание пишется
  в обоснование и в `meta.guards`.
- `backend/hints.py` + `hints` в конфиге c08: регулярки RU/KZ/EN (личная карта, «переведите мне», личный номер,
  платная консультация, в обход компании). Ищутся только в засчитываемых репликах оператора; 0 ложных на 77 диалогах.
- `backend/evaluator.py`: один вызов на критерий, параллельно; голосование `VOTES` (binary/flag — большинство,
  scale — `median_low`), `confidence`; not_evaluable без вызовов; каждый вызов в `llm_calls`; стоимость оценки
  (`db.evaluation_cost`). Кэш оценок по (диалог, версия чек-листа, версия промпта, модель, **голоса**) — `use_cache=True`.
- `eval/run.py`: `--gold`, `--votes`, `--ids`, `--no-cache`; точность по критериям, ошибка в ступенях шкалы,
  MAE итога, разбивка по языкам и каналам, таблица расхождений (reasoning, guards, автоподсказка причины,
  отметка uncertain), проверка edge (статус, факты, целевые критерии). Отчёт `eval/reports/<ts>.md` + `.json`.
- `eval/compare.py`: дельта двух JSON-отчётов по критериям, MAE, edge; списки «стали верными/неверными».

## 3. Найденное в данных (дополняет CLAUDE.md)
- Звонки: оператор начинается с «Агент присоединился к разговору с клиентом.»; события удержания

  событие записи на казахском в RU-звонке. В p4-ru-002 нет IVR. Удержание в p4-ru-002 длиннее консультации.

## 6. Применённые правки (закоммичены)
- **П1** промпт: правило 10 «каждый недостаток — ровно в одном критерии» + список остальных критериев в блоке критерия.
- **П2** R7 (c06): c06 — форма диалога; ответ не по теме/противоречия → 7; 4 — только если клиент не понял
  сформулированное; содержание → c04, переспрос → c02, тон → c05.
- **П3** R5 (c04): второстепенная деталь — то, о чём клиент спросил или без чего не выполнит совет.
- **П4** R6 (c05): определение недовольства; «я уже писал» — не недовольство; неполнота → c04.
- **П5** R3 (c02): уточнение более точной детали — не переспрос.
- **П6** R4 (c03): раскрытие — реальные данные счёта или выполненное защищённое действие; догадка — не раскрытие.
- **П8** валидатор: reasoning должно быть на русском (цитаты в «» не считаются).
- **П7 не применено** (R8 vs эталон p1-ru-029) — ждёт решения пользователя (вопрос 6 ниже).

## 9. Как запускать
```
pip install -r requirements.txt            # или .venv уже готов
cp .env.example .env                       # LLM_API_KEY=... (или ANTHROPIC_API_KEY)
.venv/bin/python -m pytest -q              # 196 passed, 1 skipped на момент записи
.venv/bin/python -m eval.run --gold eval/gold_tune.json
.venv/bin/python -m eval.run --gold eval/edge_cases.json
.venv/bin/python -m eval.compare eval/reports/A.json eval/reports/B.json
python scripts/download_audio.py           # mp3 звонков в data/audio/
```
Стоимость: ~$0.10 на диалог (1 голос, Opus 5.5, кэш промпта работает: ~90% входа читается из кэша).
Ollama/vLLM: `LLM_PROVIDER=openai`, `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=...`.
