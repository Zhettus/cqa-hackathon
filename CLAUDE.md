# CQA — Conversation Quality Analytics (хакатон Freedom Broker)

## Цель
Прототип оценки работы оператора в чатах и звонках по настраиваемому чек-листу:
баллы, обоснования, реплики-доказательства, апелляции. ГЛАВНЫЙ критерий жюри —
совпадение с эталоном на 10 новых диалогах. Задание — docs/SPEC.md.
Трактовки правил — docs/rules.md (обязательны к применению).

## Стек
- Backend: Python 3.11+, FastAPI, SQLite, httpx, pydantic v2, pytest
- LLM: через абстракцию провайдера (backend/llm/), провайдер и модель — в .env
- Frontend: чистый HTML/CSS/JS (ES modules), без сборщика и CDN. Раздаётся FastAPI.
  Пригоден как HTML web resource в Dynamics 365: самодостаточная страница,
  параметры через URL, данные только через REST API.

## Команды
- `pip install -r requirements.txt`
- `uvicorn backend.main:app --reload` → http://localhost:8000
- `pytest -q`
- `python -m eval.run --gold eval/gold_tune.json` (также edge_cases.json)

## Данные (важно знать)
- Источник: API организаторов по group_id; локально data/{group_id}.json
  (dev.json = DEV, edge.json = EDGE). Формат: data.records[].
- Чаты: время MM:SS от начала чата. Шаблон: клиент → бот (приветствие AIM,
  согласие) → эскалация → оператор. Оператор вступает после system-события
  «Эскалация на оператора» / «Чат операторға жіберілді» / «Chat transferred to an agent».
- Сообщения клиента до подключения оператора — известные оператору детали.
- Системные события: «Личность клиента подтверждена» / «Клиенттің жеке басы расталды» /
  «Customer identity verified»; «Оператор закрыл чат» / «Agent closed the chat» /
  «Оператор чатты жапты»; обрывы: «Соединение с клиентом прервано»,
  «Клиент покинул чат», «Connection to customer lost», «Клиентпен байланыс үзілді».
- Звонки: время ISO 8601, текст — шумное автораспознавание, ПДн замаскированы
  («[Имя скрыто]» и т.п.), есть IVR, DTMF («2», «#»), дубли, удержание и
  консультация с коллегой (реплики коллеги помечены operator!), реплики после
  «Клиент завершил разговор». Идентификация словесная (ФИО/ИИН/адрес/SMS-код).

## Инварианты (нарушать нельзя)
1. Чек-лист — данные (JSON с версиями). Промпт собирается из конфига.
   Новый критерий любого типа работает без правки кода.
2. Баллы, перераспределение при N/A, итоги секций и округление считает только
   backend/scoring.py. Округление — Decimal, ROUND_HALF_UP.
3. Время (первая реакция, паузы, удержание) считается в коде, не моделью.
4. Ответ LLM валидируется: N/A только где разрешён; шкала — только допустимые
   ступени; цитата есть в ОРИГИНАЛЬНОМ тексте указанной реплики. Иначе повтор.
5. Никаких заготовленных результатов. Каждая оценка — реальный вызов модели,
   логируется (модель, токены, время, стоимость, сырой ответ).
6. Исходная оценка неизменна; решения по апелляциям хранятся отдельно.
7. Оценка хранит id и версию чек-листа.
8. Исходные text и timestamp не изменяются; очищенный текст — отдельное поле.
9. Оценивается только оператор. bot, system, IVR, реплики на удержании и после
   завершения разговора оператору не засчитываются.
10. Нет реплик оператора → статус not_evaluable, итог null, LLM не вызывается.

## Правила работы
- Перед завершением задачи — `pytest -q`; задача не завершена при красных тестах.
- НЕ открывай eval/gold_holdout.json — его запускает только человек.
- НЕ изменяй файлы в eval/*.json — это разметка людей.
- Изменения промптов — только общие правила, никакой подгонки под конкретный диалог.
- Секреты только в .env. Маленькие коммиты после каждой рабочей части.
- Неоднозначность, которой нет в docs/rules.md, — спроси меня.
- UI и обоснования на русском; цитаты — на языке оригинала.
